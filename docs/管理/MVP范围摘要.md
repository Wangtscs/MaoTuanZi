# 毛团子AI · MVP 范围摘要

**版本**：V1.0 | **更新日期**：2026-08-18 | **关联文档**：`prd2.md` §7.1、`docs/管理/里程碑与发布计划.md` §阶段 1

> 本文档从 PRD 和里程碑计划中抽取**阶段 1（MVP 验证期，第 1-2 周）必须实现的功能边界**。用于开发启动前对齐范围，防止范围蔓延。

---

## 一、MVP 目标

在 2 周内上线一个可运行、可付费、可收集反馈的最小版本，验证核心假设：

| 假设 | 验证方式 | 目标 |
|------|---------|------|
| 宠物主愿意为 AI 画像付费 | 2D 画像生成后引导付费 | 付费转化率 ≥ 5% |
| 低门槛登录 + 宠物档案能降低使用成本 | 新用户完成首次画像的比例 | 首次画像完成率 ≥ 40% |
| 月卡会员有吸引力 | 月卡购买率 | 会员付费率 ≥ 3% |

> 注：PRD 中部分目标数字偏乐观，本文档将其调整为「假设 + 验证方式」的表述，便于后续根据实测数据修正。

## 二、MVP 必须实现的功能

### 2.1 用户系统

| 功能 | 说明 | 优先级 |
|------|------|:------:|
| 微信一键登录 | `wx.login()` 获取 code，后端换 openid + token | P0 |
| 游客模式 | 不登录可体验免费功能，付费时强制登录 | P1 |
| 隐私协议弹窗 | 首次进入弹出，同意后才可使用 | P0 |
| 协议同意记录 | 记录用户同意的隐私政策版本 | P0 |
| 注销账号入口 | 仅前端入口 + 后端标记，MVP 期不自动硬删除 | P2 |

### 2.2 宠物档案

| 功能 | 说明 | 优先级 |
|------|------|:------:|
| 创建宠物档案 | 昵称、品类（猫/犬/其他）、品种、性别、生日、体重、绝育、头像 | P0 |
| 宠物列表/详情/编辑/删除 | 基础 CRUD，应用层限制免费用户最多 2 只 | P0 |
| 品种字典 | 先内置 50 个常见品种，后续扩展 | P0 |

### 2.3 核心 AI 工具（MVP 只做 2D 画像）

| 功能 | 说明 | 优先级 |
|------|------|:------:|
| 2D AI 宠物画像 | 上传照片 → 选风格 → 生成低清水印预览 → 付费解锁高清 | P0 |
| 风格列表 | 免费 2 种（油画、迪士尼卡通），会员专属先不开放 | P0 |
| 作品管理 | 我的作品列表、预览、删除 | P0 |
| AI 任务编排 | 异步任务、状态查询、失败重试 | P0 |
| 症状查询 | 只做基础版：输入症状 → 输出护理参考 + 免责声明 | P1 |
| 喂养方案 | 只做基础版：基于档案生成 → 付费解锁完整内容 | P1 |
| 品种识别 | MVP 期不做，避免引入额外第三方 API 成本 | 不做 |
| 3D 手办 | MVP 期不做，阶段 3 再引入 | 不做 |

### 2.4 付费体系

| 功能 | 说明 | 优先级 |
|------|------|:------:|
| 单次付费：高清 2D 画像 | 9.9 元/张 | P0 |
| 微信支付对接 | 统一下单、支付回调、订单查询 | P0 |
| 月卡会员 | 19.9 元/月，每月 5 张高清额度 | P0 |
| 订单中心 | 我的订单、订单状态 | P0 |
| 退款 | 画像 24h 内无理由退款（人工审核即可） | P1 |
| 季卡/年卡/组合套餐 | MVP 期不做 | 不做 |
| 优惠券 | MVP 期不做 | 不做 |

### 2.5 个人中心

| 功能 | 说明 | 优先级 |
|------|------|:------:|
| 我的宠物 | 宠物档案入口 | P0 |
| 我的作品 | 画像作品列表 | P0 |
| 会员中心 | 展示当前会员状态 | P0 |
| 订单管理 | 付费记录 | P0 |
| 设置 | 隐私政策、用户协议、注销入口 | P0 |

### 2.6 小程序页面骨架

| 页面 | 说明 | 优先级 |
|------|------|:------:|
| 首页 | 核心 AI 工具入口、会员 banner | P0 |
| AI 创作页 | 2D 画像入口 | P0 |
| 养宠工具页 | 宠物档案、症状查询、喂养方案入口 | P0/P1 |
| 我的页 | 个人中心 | P0 |
| 萌宠广场 | MVP 期不做 | 不做 |

## 三、MVP 明确不做的功能

以下功能在 PRD 中有规划，但**MVP 期不做**，避免范围蔓延：

| 功能 | 原因 | 计划阶段 |
|------|------|---------|
| 3D 萌宠数字手办 | 技术复杂、成本高、需要先验证 2D 付费 | 阶段 3 |
| 萌宠广场 | UGC 审核成本高，不是核心转化路径 | 阶段 2 |
| 每日有缘毛孩子 | 社交功能，非 MVP 核心 | 阶段 2 |
| 主题打卡挑战 | 运营活动，依赖广场 | 阶段 2 |
| 证件卡/纪念卡模板 | 增值功能，2D 画像后可做 | 阶段 2 |
| 成长时光手册 | 留存功能，非核心转化 | 阶段 2 |
| 健康日程提醒 | 工具留存，依赖订阅消息申请 | 阶段 2 |
| 体重饮食记录 | 工具留存，非核心转化 | 阶段 2 |
| AI 取名 | 纯引流功能，MVP 期不做 | 阶段 2 |
| 晒宠文案 | 高频留存，MVP 期不做 | 阶段 2 |
| 表情包工坊 | 阶段 3 配合 3D 做 | 阶段 3 |
| 品种识别 | 第三方 API 成本，可用 2D 画像替代引流 | 阶段 2 |
| 季卡/年卡/组合套餐 | 付费体系复杂化，先验证月卡和单次 | 阶段 2 |
| 优惠券系统 | 运营工具，MVP 期不做 | 阶段 2 |

## 四、MVP 技术边界

| 项 | MVP 决策 | 说明 |
|----|---------|------|
| 小程序框架 | 微信原生 | 不引入 Taro/Uni-app |
| 后端框架 | NestJS + TypeScript | 按 `docs/设计/04-技术架构设计文档.md` |
| AI 网关 | Python FastAPI | 独立进程，通过队列通信 |
| 数据库 | MySQL 单库 + Redis | 不分库 |
| 部署 | Docker Compose 单机 | 不上 K8s |
| 文件存储 | 阿里云 OSS | 境内区域 |
| 3D 渲染 | 不做 | 阶段 3 再评估 |
| 实时推送 | 不做 WebSocket | 用微信订阅消息 + 轮询 |

## 五、验收标准

### 5.1 功能验收

- [ ] 新用户首次进入能看到隐私协议弹窗，同意后可进入首页
- [ ] 不登录可浏览，付费/保存作品时强制登录
- [ ] 可创建、编辑、删除宠物档案
- [ ] 可上传照片生成 2D 画像低清水印预览
- [ ] 预览页可触发微信支付，支付成功后返回高清无水印图
- [ ] 月卡会员可正常开通，权益即时生效
- [ ] 订单中心可查看历史订单
- [ ] 症状查询和喂养方案页面有固定免责声明

### 5.2 技术指标

| 指标 | 目标 |
|------|------|
| 小程序首屏加载 | ≤ 3 秒（MVP 期放宽到 3 秒） |
| API P99 延迟 | ≤ 500ms |
| 2D 画像生成耗时 | ≤ 15 秒（从提交到预览生成） |
| 支付成功率 | ≥ 95% |
| 服务可用性 | ≥ 99%（单机可用性） |

### 5.3 业务指标

| 指标 | 目标 | 验证周期 |
|------|------|---------|
| 新用户首次画像完成率 | ≥ 40% | 上线后 1 周 |
| 2D 画像付费转化率 | ≥ 3%（保守）/ ≥ 5%（乐观） | 上线后 2 周 |
| 月卡购买率 | ≥ 1% | 上线后 2 周 |
| 核心流程可用率 | 100% | 持续 |

## 七、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 2D 画像效果不达标 | 用户不付费 | 先多测几家服务商，MVP 期只保留效果最好的 2 种风格 |
| 微信支付接入复杂 | 延迟上线 | 提前申请商户号，先接沙箱环境 |
| 微信审核不通过 | 无法上线 | 选「工具 → 效率」类目，避免医疗/社交敏感功能 |
| AI 成本过高 | 亏损 | 免费用户仅生成低清水印，控制免费额度 |
| 转化率低于预期 | 商业模式不成立 | 2 周内未达到 3% 转化率，暂停扩张，优化定价/风格 |
