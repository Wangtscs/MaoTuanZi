# 毛团子AI · 待验证假设与实测计划

**版本**：V1.0 | **更新日期**：2026-08-18 | **关联文档**：`prd2.md`、`docs/设计/04-技术架构设计文档.md`、`docs/管理/ADR.md`

> 本文档汇总项目当前所有「待实测」「待验证」「未决」事项，形成可跟踪的实测计划。每条记录都有验证方法、验收标准和截止时间。

---

## 一、使用说明

| 状态 | 含义 |
|------|------|
| ⏳ 待验证 | 尚未开始验证 |
| 🔄 验证中 | 正在进行测试或收集数据 |
| ✅ 已验证 | 已达到验收标准，结果已记录 |
| ❌ 验证失败 | 未达验收标准，需要调整方案 |
| ⚠️ 部分验证 | 部分达标，需要折中或继续优化 |

**更新规则**：每次验证完成后，更新「验证结果」和「状态」，并把关键结论同步回源文档（如 ADR、架构文档、PRD）。

## 二、AI 服务商选型验证

### 2.1 大语言模型（症状查询 / 喂养方案 / 文案 / 取名）

| 项 | 内容 |
|----|------|
| 假设 | 国产大模型在宠物垂直场景下效果可接受，成本可控 |
| 候选服务商 | 豆包、DeepSeek、智谱 GLM |
| 验证方法 | 准备 10 个典型用例（症状护理、喂养建议、晒宠文案、宠物取名），分别调用候选模型，从效果、延迟、价格三维度评分 |
| 验收标准 | ① 输出内容符合医疗免责声明要求，不越界；② 平均响应 ≤ 3s；③ 成本 ≤ 0.05 元/次 |
| 优先级 | 🔴 P0 |
| 截止时间 | 阶段 1 启动后 3 天内 |
| 负责人 | 后端/AI 网关 |
| 状态 | ⏳ 待验证 |
| 验证结果 | — |

### 2.2 图生图（2D 宠物画像）

| 项 | 内容 |
|----|------|
| 假设 | 单图生成宠物艺术画像可达到商业可用效果，宠物五官还原度足够高 |
| 候选服务商 | 通义万相、豆包图像、Replicate |
| 验证方法 | 准备 10 张不同品种/角度的宠物照片，测试 5 种风格（油画、迪士尼卡通、水彩、赛博朋克、证件照），评估还原度、生成时间、成本 |
| 验收标准 | ① 10 张中 ≥ 7 张用户可识别为自家宠物；② 生成时间 ≤ 15s；③ 成本 ≤ 1 元/次（高清） |
| 优先级 | 🔴 P0 |
| 截止时间 | 阶段 1 启动后 5 天内 |
| 负责人 | 后端/AI 网关 |
| 状态 | ⏳ 待验证 |
| 验证结果 | — |

### 2.3 单图 3D 生成

| 项 | 内容 |
|----|------|
| 假设 | 单图生成 3D 宠物模型在成本和效果上可用于商业化 |
| 候选服务商 | Tripo3D、Meshy、Luma |
| 验证方法 | 准备 10 张正面全身宠物照，测试快速模式生成效果：模型完整性、毛发/毛色还原、穿模情况、文件大小 |
| 验收标准 | ① 10 张中 ≥ 6 张可生成可用模型；② 生成时间 ≤ 30s；③ GLB 文件 ≤ 5MB；④ 成本 ≤ 5 元/次 |
| 优先级 | 🟠 P1（MVP 期不阻塞，阶段 3 前必须验证） |
| 截止时间 | 阶段 2 结束前 |
| 负责人 | AI 网关/3D 前端 |
| 状态 | ⏳ 待验证 |
| 验证结果 | — |

## 三、性能与容量验证

### 3.1 单 ECS 实际承载量

| 项 | 内容 |
|----|------|
| 假设 | MVP 期 4 核 8G ECS 可支撑日活 1000 用户 |
| 验证方法 | 使用压测工具模拟 100/500/1000 并发用户，测试 API 延迟、错误率、CPU/内存占用 |
| 验收标准 | ① P99 延迟 ≤ 500ms；② 错误率 ≤ 1%；③ CPU 峰值 ≤ 70% |
| 优先级 | 🟠 P1 |
| 截止时间 | 阶段 1 上线前 |
| 负责人 | 后端/运维 |
| 状态 | ⏳ 待验证 |
| 验证结果 | — |

### 3.2 AI 任务平均耗时

| 项 | 内容 |
|----|------|
| 假设 | 2D 画像平均生成时间 ≤ 15s，3D 快速模式 ≤ 30s |
