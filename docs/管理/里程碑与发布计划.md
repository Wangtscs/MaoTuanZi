## 三、版本节奏

### 3.1 发布频率

| 类型 | 频率 | 说明 |
|------|------|------|
| 紧急修复（hotfix）| 随时 | 24h 内修复生产 bug |
| 常规发布 | 每周二 | 累积一周的小功能 / 修复 |
| 小版本（minor）| 每月 | 阶段 2/3 类新增功能 |
| 大版本（major）| 每季度 | 阶段 4/5/6 类里程碑 |

### 3.2 发布窗口

- 周二 14:00-16:00（业务低峰）
- 避免周五、节假日前发布

## 四、发布流程

### 4.1 流程图

```
开发 → Code Review → CI 通过 → 合并 develop
    ↓
集成测试（staging）
    ↓
QA 验证（QA / 创始人）
    ↓
合并 main → tag
    ↓
CD 部署（蓝绿）
    ↓
健康检查 → 灰度 5% → 全量
    ↓
发布后监控（1h 内）
```

### 4.2 发布 Checklist

- [ ] 所有 P0 测试通过
- [ ] Code Review 至少 1 人
- [ ] 数据库迁移脚本就绪（含回滚）
- [ ] 配置变更已确认
- [ ] 监控 / 告警配置
- [ ] 回滚预案已就绪
- [ ] 公告已准备（必要时）
- [ ] 客服已被告知

## 五、版本号规则

遵循 [语义化版本](https://semver.org/lang/zh-CN/)：

| 位置 | 含义 | 触发 |
|------|------|------|
| MAJOR | 不兼容变更 | 架构调整、协议变更 |
| MINOR | 向兼容功能新增 | 新功能、新模块 |
| PATCH | 向兼容修复 | Bug 修复、性能优化 |

示例：`v1.2.3`
