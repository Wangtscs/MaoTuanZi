# 毛团子AI · 用户反馈与需求管理流程

**版本**：V1.0 | **更新**：2026-08-18

> 把用户反馈**系统化**为产品迭代输入，避免"反馈进来没人管"。

---

## 一、反馈渠道

| 渠道 | 适用 | 优先级 |
|------|------|:---:|
| 小程序内"意见反馈" | 主要 | 🟢 |
| 客服微信 | 紧急 | 🟡 |
| 客服邮箱 | 异步 | 🟢 |
| 社群 | 集中收集 | 🟢 |

## 二、反馈分类

### 2.1 标签体系

```
类型:  bug / feature / content / ux / other
来源:  in-app / wechat / community
紧急度: P0-P3
模块:  user / pet / ai / order / vip / tool / square / system
```

### 2.2 优先级

| 等级 | 触发 |
|------|------|
| P0 | 影响核心功能使用、数据丢失、安全 |
| P1 | 影响付费流程、体验明显问题 |
| P2 | 体验问题但不阻塞 |
| P3 | 建议、咨询 |

## 三、处理 SOP

### 3.1 接收（T+0）

1. 客服收到反馈 → 打标签 → 入库
2. 自动回复用户"已收到，X 工作日内回复"
3. P0/P1 立即通知产品负责人

### 3.2 分类（T+1）

| 类别 | 流向 |
|------|------|
| Bug | 技术负责人 → 修复排期 |
| Feature | 产品负责人 → 需求池 |
| Content | 运营负责人 → 文案优化 |
| UX | 产品负责人 → 设计优化 |
| Other | 客服回复 |

### 3.3 响应时效

| 优先级 | 首次响应 | 关闭 |
|--------|---------|------|
| P0 | 30 分钟 | ≤ 24h |
| P1 | 4 小时 | ≤ 3 天 |
| P2 | 1 天 | ≤ 7 天 |
| P3 | 3 天 | ≤ 14 天 |

### 3.4 关闭

- 给用户最终回复（"已修复 / 已采纳 / 已记录待评估"）
- 更新反馈状态
- 关闭后不再回访

## 四、需求池管理

### 4.1 来源

- 用户反馈（≥ 3 次提同一需求 → 升级）
- 运营观察
- 竞品分析
- 数据驱动

### 4.2 评估维度

| 维度 | 评估 |
|------|------|
| 用户价值 | 多少用户受影响？ |
| 商业价值 | 对付费转化的影响？ |
| 实施成本 | 工作量 / 复杂度 |
| 风险 | 合规 / 安全 / 性能 |
| 依赖 | 与其他需求的关系 |

### 4.3 决策

```
优先级 = (用户价值 × 商业价值) / 实施成本
```

| 评分 | 决策 |
|------|------|
| ≥ 10 | P0，立即做 |
| 5-10 | P1，本季度 |
| 2-5 | P2，下季度 |
| < 2 | 不做 |

## 五、数据看板

### 5.1 必看指标

| 指标 | 用途 |
|------|------|
| 每日反馈数 | 监测异常 |
| 按类型分布 | 识别问题模式 |
| 按优先级分布 | 资源分配 |
| 平均响应时长 | 客服效率 |
| 关闭率 | 处理完成度 |

### 5.2 复盘

每周复盘：

- 本周反馈 Top 5
- 已修复 / 已采纳数
- 待评估需求数
- 下周重点
