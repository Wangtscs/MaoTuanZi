# 毛团子AI · 数据埋点与指标体系文档

**版本**：V2.0 | **更新日期**：2026-08-18

> 本文档定义埋点规范、核心事件、KPI 指标与看板设计。**所有 KPI 阈值需根据实际业务调整**，本文为指标体系框架。

---

## 一、埋点目标

1. **量化核心业务**：付费转化、留存、客单价、API 成本
2. **驱动产品迭代**：发现体验瓶颈、支撑 A/B 测试
3. **用户分层运营**：新 / 活 / 付 / 流四类用户差异化策略
4. **预警风险**：异常指标自动告警

---

## 二、埋点架构

### 2.1 数据流

```
客户端（小程序）
    ↓ SDK 上报（带 trace_id）
后端 API 接收（统一入口 /v1/track）
    ↓ 校验 + 富化（user_id、session）
    ├→ 异步队列（实时）
    └→ 数据仓库（离线分析）
```

### 2.2 接入方式

| 端 | SDK | 备注 |
|----|-----|------|
| 小程序 | 自研 `mt-track-mp` | wx.request 封装 + 本地缓存重试 |
| 后端 | 自研 `mt-track-node` | 异步批量上报 |
| AI 网关 | 自研 `mt-track-py` | 装饰器埋点 |

### 2.3 事件公共属性（必传）

| 字段 | 类型 | 必传 | 说明 |
|------|------|:---:|------|
| event_id | string | ✅ | 客户端生成的 UUID（去重） |
| event_name | string | ✅ | 事件名（见 §3 命名规范） |
| timestamp | int64 | ✅ | 客户端时间戳（毫秒） |
| user_id | int64 | ❌ | 未登录时为空 |
| openid | string | ❌ | 微信 OpenID |
| session_id | string | ✅ | 会话 ID（页面打开到关闭） |
| trace_id | string | ✅ | 请求链路 ID |
| app_version | string | ✅ | 客户端版本 |
| client | string | ✅ | miniprogram / server |
| platform | string | ❌ | wechat / ios / android |
| system_version | string | ❌ | iOS 17.0 等 |
| device_model | string | ❌ | iPhone 14 等 |
| network | string | ❌ | wifi / 4g / 5g |

## 五、KPI 指标体系

### 5.1 指标设计原则

| 原则 | 含义 |
|------|------|
| 可衡量 | 有明确计算公式 |
| 可对比 | 有同期 / 同期对比基准 |
| 可行动 | 指标变化能驱动具体动作 |
| 有限性 | 每个模块不超过 5 个核心指标 |

### 5.2 拉新指标

| 指标 | 公式 | 说明 |
|------|------|------|
| 日新增用户 DNU | 当日新注册用户数 | 绝对值 |
| 注册转化率 | 注册数 / 打开次数 | 漏斗转化 |
| 邀请转化率 | 成功邀请数 / 邀请发出数 | 裂变效率 |
| CAC | 总营销成本 / 新增用户 | 待实测 |

### 5.3 活跃指标

| 指标 | 公式 | 说明 |
|------|------|------|
| DAU | 当日活跃用户数 | - |
| MAU | 当月活跃用户数 | - |
| DAU/MAU | DAU / MAU | 黏性 |
| 次日留存 | 次日仍活跃 / 当日新用户 | 短期黏性 |
| 7 日留存 | 7 日后仍活跃 | - |
| 30 日留存 | 30 日后仍活跃 | 长期黏性 |

### 5.4 功能使用指标

| 指标 | 公式 | 说明 |
|------|------|------|
| 功能渗透率 | 使用某功能的 DAU / 总 DAU | 功能采用度 |
| 人均 AI 生成次数 | 总生成任务数 / DAU | 工具使用频次 |
| 广场 PV | 总浏览数 | - |
| 广场 UV | 浏览用户数 | - |

### 5.5 付费指标（核心商业指标）

| 指标 | 公式 | 说明 |
|------|------|------|
| 付费转化率 | 付费用户数 / DAU | 整体付费比例 |
| 会员付费率 | 会员用户数 / DAU | 订阅转化 |
| ARPU | 总收入 / MAU | 单用户价值 |
| ARPPU | 总收入 / 付费用户数 | 付费用户价值 |
| 客单价 | 总收入 / 订单数 | 单笔均价 |
| 退款率 | 退款订单数 / 总订单数 | 满意度反向指标 |
| 净收入 | 收入 - 退款 | - |
| MRR | 月度经常性收入 | 订阅业务 |

> **注**：所有阈值（5%、8%、30% 等）需结合实际业务调整，本文档不固化数字。

### 5.6 成本指标

| 指标 | 公式 | 说明 |
|------|------|------|
| API 单位成本 | API 总成本 / MAU | 单用户 AI 成本 |
| 单订单成本 | API 成本 / 订单数 | 单笔成本 |
| 毛利率 | (收入 - 成本) / 收入 | 商业健康度 |

### 5.7 内容生态指标

| 指标 | 公式 | 说明 |
|------|------|------|
| 广场 UGC 日产 | 每日新增公开作品 | 内容供给 |
| 帖子平均点赞 | 总点赞 / 帖子数 | 内容质量 |
| 互动率 | 点赞数 / 帖子浏览数 | - |
| 内容审核拦截率 | 拦截数 / 审核总数 | 合规反向指标 |

## 六、用户分层指标

### 6.1 RFM 模型

| 维度 | 划分 |
|------|------|
| Recency（最近活跃） | R1-R5（5 档） |
| Frequency（使用频次） | F1-F5 |
| Monetary（消费金额） | M1-M5 |

### 6.2 四类用户

| 类型 | 定义 | 运营策略 |
|------|------|---------|
| 新用户 | 注册 ≤ 7 天 | 首单优惠 |
| 活跃用户 | 7 日内活跃 ≥ 3 天 | 推送新功能 |
| 付费用户 | 累计付费 ≥ 1 元 | 升级优惠 |
| 流失用户 | 30 日未活跃 | 召回福利 |

### 6.3 漏斗模型

以「注册 → 付费」为例：

```
打开 → 注册 → 创建宠物 → 进入 AI → 生成预览 → 付费 → 7 日留存
```

每一步计算转化率，定位流失节点。

## 九、隐私合规

### 9.1 埋点合规原则

- ✅ 埋点前阅读隐私政策
- ✅ 不收集与服务无关的信息
- ✅ 设备 ID 匿名化
- ✅ 不上报用户输入的原始文本 / 图片内容
- ❌ 不上报精确位置（仅省级）
- ❌ 不上报通讯录、短信

### 9.2 用户权利

- 用户可在「设置 → 隐私」关闭个性化推荐
- 用户注销后 **30 天内** 删除全部埋点数据

## 十、关键 SQL 模板

### 10.1 今日 DAU

```sql
SELECT COUNT(DISTINCT user_id)
FROM events
WHERE event_name = 'app_launched'
  AND DATE(server_timestamp) = CURDATE();
```

### 10.2 付费转化漏斗

```sql
SELECT
  COUNT(DISTINCT IF(event_name='app_launched', user_id, NULL)) AS dau,
  COUNT(DISTINCT IF(event_name='ai_page_viewed', user_id, NULL)) AS ai_viewers,
  COUNT(DISTINCT IF(event_name='ai_task_created', user_id, NULL)) AS ai_users,
  COUNT(DISTINCT IF(event_name='order_paid', user_id, NULL)) AS payers
FROM events
WHERE DATE(server_timestamp) = CURDATE();
```

### 10.3 7 日留存

```sql
WITH new_users AS (
  SELECT user_id, MIN(DATE(server_timestamp)) AS register_date
  FROM events
  WHERE event_name = 'user_registered'
  GROUP BY user_id
)
SELECT
  register_date,
  COUNT(DISTINCT u.user_id) AS new_count,
  COUNT(DISTINCT IF(t.active_date = u.register_date + INTERVAL 7 DAY, u.user_id, NULL)) AS d7_retention
FROM new_users u
LEFT JOIN (
  SELECT user_id, DATE(server_timestamp) AS active_date
  FROM events
  WHERE event_name = 'app_launched'
  GROUP BY user_id, DATE(server_timestamp)
) t USING (user_id)
GROUP BY register_date;
```
