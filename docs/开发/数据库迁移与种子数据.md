## 一、迁移工具

### 1.1 推荐：TypeORM Migrations（NestJS）

```typescript
// apps/api/src/data-source.ts
import { DataSource } from 'typeorm';
import * as dotenv from 'dotenv';

dotenv.config();

export default new DataSource({
  type: 'mysql',
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT),
  username: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  entities: ['src/**/*.entity.ts'],
  migrations: ['src/migrations/*.ts'],
  synchronize: false,  // 生产必须 false
});
```

### 1.2 命令

```bash
# 生成迁移文件（基于实体变更）
pnpm run migration:generate -- src/migrations/AddFieldName

# 执行迁移
pnpm run migration:run

# 回滚最后一次
pnpm run migration:revert

# 查看迁移状态
pnpm run migration:show
```

### 1.3 迁移文件命名

```
src/migrations/
├── 1700000000000-CreateInitialSchema.ts
├── 1700000001000-AddPetsBirthdayIndex.ts
├── 1700000002000-AddFeedingPlansAdjustCount.ts
└── ...
```

格式：`timestamp-CamelCaseDescription.ts`

## 二、迁移规范

### 2.1 强制规则

- ❌ **禁止**在生产环境使用 `synchronize: true`
- ❌ **禁止**手动修改已部署的表结构
- ❌ **禁止**直接执行原始 SQL DDL
- ✅ 所有变更必须通过迁移文件
- ✅ 迁移文件必须有 `up()` 和 `down()` 方法
- ✅ 大表 ALTER 使用 `pt-online-schema-change`

### 2.2 迁移审查清单

提交 PR 前：

- [ ] 迁移文件有 `up` 和 `down`
- [ ] `down` 可逆回（不影响数据）
- [ ] 大表操作有性能评估
- [ ] 已添加必要的索引
- [ ] 测试环境验证通过

## 四、初始化流程

### 4.1 新环境首次启动

```bash
# 1. 启动 MySQL + Redis
docker compose up -d

# 2. 执行迁移（创建表）
cd apps/api
pnpm run migration:run

# 3. 导入种子数据
pnpm run seed

# 4. 验证

```

## 五、回滚策略

### 5.1 迁移失败回滚

```bash
# 单次回滚
pnpm run migration:revert

# 全部回滚（危险操作）
pnpm run migration:revert -- --all
```

### 5.2 数据损坏恢复

1. 停止应用
2. 从备份恢复（详见 [`/docs/部署运维/部署SOP.md`](../部署运维/部署SOP.md) § 备份恢复）
3. 验证数据完整性
4. 重启应用
